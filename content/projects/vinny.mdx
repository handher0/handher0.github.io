## 개요

- **인원** 백엔드 4명
- **역할** 커뮤니티 도메인(게시글·좋아요·북마크·피드)


## 기술 스택
Java 17 · Spring Boot 3 · Spring Data JPA · MySQL · AWS EC2·RDS · Docker · GitHub Actions

## 핵심 문제 해결

### 1. 피드 조회 N+1 — 페이지당 쿼리 71회 → 6회
- **문제** 기능은 정상이었지만 SQL 로그를 보니 피드 한 페이지(10건)에서 게시글마다 작성자·이미지·좋아요·해시태그 조회가 따로 나갔습니다.
- **원인** 연관 엔티티를 지연 로딩으로 하나씩 불러오는 N+1 구조
- **해결** 작성자·이미지는 `fetch join`, 나머지 컬렉션 5종은 `@BatchSize(10)`로 묶음
- **결과** 페이지당 쿼리 71회 → 6회 *(코드 구조 기준 계산: 1+10+10+10×5 → 1+5)*

### 2. 인기순 조회 — 컬렉션 fetch join과 페이징 충돌
- **문제** 컬렉션을 fetch join한 채 페이징하면 DB가 아닌 메모리에서 페이징이 일어남
- **해결** 좋아요순으로 게시글 ID만 먼저 페이징 → 해당 ID로 연관 데이터를 가져오는 2단계 쿼리

### 3. 이미지 중복 조회
- **원인** 여러 컬렉션을 한 번에 조인해 결과 행이 곱해짐
- **해결** 조인 범위를 줄이고, `@OrderBy`로 이미지 순서 보장

## 팀 작업
